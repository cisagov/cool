# IAM User Management

**Purpose:** To manage AWS IAM users in COOL Production or COOL Staging-a by
creating or removing accounts and/or modifying group memberships.

IAM users are managed as code: user and group membership lists live in the
private `cool-tfvars` repository, and changes are applied with Terraform from
the corresponding group repository (e.g. `cool-users-non-admin`).

**Prerequisites:** You MUST complete
[Admin Workstation Setup](Admin-Workstation-Setup.md) before proceeding.

---

## Creating a user account and adding it to groups

### Step 1: Edit the cool-users-non-admin file in the cool-tfvars repository

1. Go to the `cool-tfvars` repository on GitHub, which lists all the groups
   for both COOL Production and Staging-a.
1. Select `cool-users-non-admin`, then select the `production.tfvars` file
   (or `staging-a.tfvars` for Staging-a).
1. Ensure that you are on the `master` branch.
1. Edit the file by adding the user **in alphabetical order**.
1. Set the MFA flag appropriately:
    - Users provisioning COOL environments and CyHy provisioners:
      `{ "require_mfa" = false, "self_managed" = true }`
    - All other users: `{ "require_mfa" = true, "self_managed" = true }`
1. Click "Commit changes", add a helpful description such as
   `add new cool-users-non-admin user john.doe`, and commit.

### Step 2: Pull and apply the changes with Terraform

```console
cd ~/code/cisagov/cool-tfvars
git pull
cd ~/code/cisagov/cool-users-non-admin
git pull
```

**For COOL Production:**

1. If you were previously working on the Staging-a backend, switch to the
   production backend:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/credentials terraform init -upgrade -reconfigure -backend-config=production.tfconfig
    ```

1. If you did not need to reconfigure the backend, simply initialize
   Terraform: `terraform init -upgrade`
1. Display the available Terraform workspaces: `terraform workspace list`
1. Select the production workspace: `terraform workspace select production`
1. Apply the changes: `terraform apply -var-file=production.tfvars`
1. When prompted to continue, examine the Terraform output for correctness.
1. If the output is correct, type `yes` to apply the changes (type `no` to
   exit if you are unsure of the output).

**For COOL Staging-a:**

1. Initialize the Staging-a backend:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/cool-staging-a-credentials terraform init -upgrade -reconfigure -backend-config=staging-a.tfconfig
    ```

1. If you did not need to reconfigure the backend, simply initialize
   Terraform:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/cool-staging-a-credentials terraform init -upgrade
    ```

1. Display the available Terraform workspaces:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/cool-staging-a-credentials terraform workspace list
    ```

1. Select the staging-a workspace:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/cool-staging-a-credentials terraform workspace select staging-a
    ```

1. Apply the changes:

    ```console
    AWS_SHARED_CREDENTIALS_FILE=~/.aws/cool-staging-a-credentials terraform apply -var-file=staging-a.tfvars
    ```

1. When prompted to continue, examine the Terraform output for correctness.
1. If the output is correct, type `yes` to apply the changes (type `no` to
   exit if you are unsure of the output).

### Step 3: Verify the user in the AWS console and enable console access

1. Log into the AWS console for COOL Production or COOL Staging-a.
1. Switch your role to the Users account of the appropriate COOL instance.
1. Click IAM.
1. Click "Users" and select the user you created.
1. Click the "Security credentials" tab.
1. Click "Enable console access", then select "Enable".
1. Select "Autogenerated password".
1. Select "User must create new password at next sign-in".
1. Click "Apply".
1. A pop-up window will show the sign-in link for the AWS console, the user's
   name, and their initial password.
1. Copy and save this information for use in Step 7.

### Step 4: Edit the file(s) of the group(s) the user should be added to

**IMPORTANT:** When in doubt about which groups to add a user to, ask a
member of the DevSecOps team.

**NOTE:** A user cannot be a member of both `cool-admin-provisioner-iam` and
`cool-assessment-provisioner-iam` at the same time.

1. Go to the `cool-tfvars` repository on GitHub and select the group the
   user needs to be added to (e.g. `cool-admin-provisioner-iam`).
1. In the group's directory, select the `production.tfvars` file (or
   `staging-a.tfvars` for Staging-a).
1. Ensure that you are on the `master` branch.
1. Edit the file by adding the user in alphabetical order.
1. Click "Commit changes", add a helpful description such as
   `add new <group name> user john.doe`, and commit.

**IMPORTANT:** If the user must be added to additional groups, repeat this
step until the user has been added to all required groups.

### Step 5: Pull and apply the changes with Terraform

```console
cd ~/code/cisagov/cool-tfvars
git pull
cd ~/code/cisagov/<group name>
git pull
```

Then run the same Terraform sequence as in Step 2 (init/reconfigure the
backend for the appropriate COOL instance, select the workspace, and
`terraform apply` with the matching `-var-file`).

**IMPORTANT:** Repeat this step for every group the user was added to in
Step 4.

### Step 6: Verify the group memberships

1. Log into the AWS console for COOL Production or COOL Staging-a.
1. Switch your role to the Users account of the appropriate COOL instance.
1. Click IAM.
1. Click "Users" and select the user.
1. Click the "Groups" tab.
1. Verify the user is assigned to the groups from Step 5.

You have successfully created the user's IAM account and added them to the
appropriate group(s).

### Step 7: Edit and send the IAM user account login email

Use the standardized email text below, modify it with the user's information
from the end of Step 3, and email it to the user. Do NOT include the initial
password in the email — deliver it out-of-band (e.g. via Teams chat), as the
template describes.

> \<FIRSTNAME LASTNAME\>,
>
> I have created your new AWS IAM user account in the COOL "Users" account and you have been added to the \<group names\> groups.
> This will allow you to \<insert short description of what the groups will allow the user to do\> in the COOL.
>
> Instructions:
>
> 1) Go to the COOL AWS web console login: `https://<account number>.signin.aws.amazon.com/console`
> 2) Your IAM user name(s) is: \<firstname.lastname\>
> 3) Ping me on Teams chat and I will give you your initial password, which must be changed at your first login.
> 4) After you have successfully logged in, you must set up your MFA device. I recommend using an authenticator app on your phone.
> 5) To set up your MFA, find the dropdown menu in the upper right part of the AWS console (it will show "\<firstname.lastname\> @ \<account number\>") and select "My Security Credentials" from it. Then click "Assign MFA device", select "Virtual MFA device", click "Continue", and follow the instructions on the next screen. If you have any trouble, check with the other members of your immediate team first, but if you are still stuck after that, feel free to ask us.
> 6) IMPORTANT: Once your MFA device is set up, log out and log back in to ensure that you are able to use your new password and your MFA. If you do not do this step, things will not work as expected.
>
> If you need to switch roles there is additional information on switching roles at: https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-console.html
>
> Hopefully that is enough to get you started, but please let us know if you have any questions.
>
> Thanks, COOL Support

## Removing a user from groups and deleting the user account

### Step 1: Remove the user's group memberships on GitHub

Remove the user as a member of each group **except** `cool-users-non-admin`,
which you will do in the last step.

1. Go to the `cool-tfvars` repository on GitHub and search for the user in
   that repository. This gives you a list of all the groups the user is in.
1. Select a group, then select the `production.tfvars` file (or
   `staging-a.tfvars` for Staging-a).
1. Ensure that you are on the `master` branch.
1. Edit the file by removing the user.
1. Click "Commit changes", add a helpful description such as
   `remove user john.doe`, and commit.
1. Repeat for every other group the user is in, except
   `cool-users-non-admin`.

### Step 2: Pull and apply the changes with Terraform

```console
cd ~/code/cisagov/cool-tfvars
git pull
cd ~/code/cisagov/<group-name>
git pull
```

**IMPORTANT:** Do this for each group that you removed the user from.

Then run the same Terraform sequence as in "Creating a user account" Step 2
(init/reconfigure the backend for the appropriate COOL instance, select the
workspace, and `terraform apply` with the matching `-var-file`).

### Step 3: Verify removal in the AWS console and disable console access

1. Log into the AWS console for COOL Production or COOL Staging-a.
1. Switch your role to the Users account of the appropriate COOL instance.
1. Click IAM.
1. Click "Users" and select the user.
1. Click the "Groups" tab.
1. The group(s) should no longer be listed. (If groups are still listed,
   repeat Steps 1 and 2 until none remain.)

If the user had AWS console access:

1. Click "Security credentials".
1. Click "Manage console access".
1. Select "Disable" and click "Apply".

If the user had an MFA device set, remove it:

1. Under Multi-Factor Authentication (MFA), select the radio button to the
   left of "Virtual".
1. Click "Remove".

### Step 4: Remove the user from cool-users-non-admin

1. Go to the `cool-tfvars` repository on GitHub, find
   `cool-users-non-admin`, and select the `production.tfvars` file (or
   `staging-a.tfvars` for Staging-a).
1. Ensure that you are on the `master` branch.
1. Edit the file by removing the user.
1. Click "Commit changes", add a helpful description such as
   `remove user john.doe`, and commit.

### Step 5: Pull and apply the cool-users-non-admin change with Terraform

```console
cd ~/code/cisagov/cool-tfvars
git pull
cd ~/code/cisagov/cool-users-non-admin
git pull
```

Then run the same Terraform sequence as before for the appropriate COOL
instance (init, select workspace, `terraform apply` with the matching
`-var-file`).

Finally, check the AWS console to make sure the IAM user was removed from the
user list in Production or Staging-a.
